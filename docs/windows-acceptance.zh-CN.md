# Windows 端双账号验收清单

> 目的:在进入 iOS 之前,把"多账号 + 共用动作库 + 离线训练闭环"在 Windows 上完整验一遍。
> 适用版本:本次新增注册、同步扩展、下架、建议弹层之后的代码。

## 0. 环境准备

```powershell
# 1) 后端配置:打开注册开关
# 编辑 backend\.env,加入:
#   REGISTRATION_ENABLED=true

# 2) 启动 PostgreSQL(如未启动)
powershell -ExecutionPolicy Bypass -File tools\restart-training-book-postgres.ps1

# 3) 迁移到最新(head = 0013)
cd D:\self\training-book\backend
..\.venv\Scripts\alembic.exe -c alembic.ini upgrade head

# 4)(可选)导入 10 个种子动作(发布为系统动作 + 一个动作库 release)
..\.venv\Scripts\python.exe -m app.cli.import_exercises

# 5) 启动后端
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 6) 启动客户端(另开窗口)
cd D:\self\training-book\apps\client_flutter
D:\tools\flutter\bin\flutter.bat run -d windows
```

Owner 账号若还没有,先用 CLI 创建(只能有一个 owner):

```powershell
cd D:\self\training-book\backend
..\.venv\Scripts\python.exe -m app.cli.bootstrap_owner --email 你的邮箱 --display-name Owner --password-env TB_OWNER_PW
# 先设置 $env:TB_OWNER_PW = '至少12位密码'
```

## 1. 注册与权限(场景 A)

| # | 操作 | 预期 |
|---|---|---|
| A1 | 登录页出现"注册账号"按钮(REGISTRATION_ENABLED=true 时) | 显示 |
| A2 | 注册一个普通账号(如 `trainee@example.com`,密码 ≥12 位) | 注册成功直接进入主界面 |
| A3 | 注册页两次密码不一致 | 被拦截提示 |
| A4 | 用同一邮箱再次注册 | 提示"这个邮箱已经注册过" |
| A5 | 普通账号进"动作库"页 | 只有已发布动作;**没有**"新增动作"按钮、草稿、修订菜单 |
| A6 | 退出登录 → 登录页关闭注册开关的服务器(注释 REGISTRATION_ENABLED) | "注册账号"按钮消失(重启后端后生效) |

## 2. 动作库管理(场景 B,owner)

| # | 操作 | 预期 |
|---|---|---|
| B1 | 用 owner 登录,动作库页出现"新增动作"按钮和草稿入口 | 显示 |
| B2 | 新建动作(仅填名称)→ 发布 | 出现在已发布列表,普通账号 A5 步骤刷新后也能看到(共用动作库) |
| B3 | 打开该动作详情 → owner 可见"下架"按钮 | 显示 |
| B4 | 下架动作 | 确认后详情页关闭;已发布列表不再出现该动作 |
| B5 | 用该动作创建新计划 | 动作库选择器里已找不到它(下架生效) |
| B6 | 普通账号打开下架前的训练历史 | 历史快照仍显示动作名(历史不受影响) |

## 3. 计划 → 训练闭环(场景 C,普通账号)

| # | 操作 | 预期 |
|---|---|---|
| C1 | 普通账号"新建训练计划",添加 2 个阶段、每阶段 1 个动作,设置组数/次数/重量/RPE | 保存成功 |
| C2 | 打开计划 → "开始本次训练" | 进入训练页,按阶段/顺序显示动作与组 |
| C3 | 每项填重量/次数 → 保存 | 显示"第 N 组已保存",进度条推进 |
| C4 | 全部组完成 → "完成训练" | 弹出"下次重量建议"面板:有加重/维持建议 + 依据文案 |
| C5 | 点"接受建议"或"忽略" | 面板正常收起,返回计划页 |
| C6 | 进度页查看当天记录 | 该训练出现在历史中,组数据与录入一致 |

## 4. 离线闭环(场景 D,核心)

> 方法:训练中途关掉后端进程(或断网),模拟健身房无网络。

| # | 操作 | 预期 |
|---|---|---|
| D1 | 在线开始训练后**杀掉后端进程**,继续记录一组 | 提示"已离线保存 1 组,等待同步";训练页顶部显示离线横幅 |
| D2 | 完全离线状态下(后端未启动)重新打开 app → 今天页 | 显示"继续训练",可恢复该会话(本地缓存) |
| D3 | 离线补记剩余组 → 完成训练 | 提示"训练已离线完成,联网后同步";不报错 |
| D4 | 重启后端 → 设置页/今天页点"同步" | 状态变为"离线记录已同步";待同步计数归零 |
| D5 | 进度页查看离线完成的训练 | 该训练与组记录完整出现(服务端已落库) |

## 5. 数据隔离(场景 E)

| # | 操作 | 预期 |
|---|---|---|
| E1 | 普通账号 A 创建的计划/训练 | 普通账号 B 登录后完全看不到 |
| E2 | 动作库(已发布动作) | 所有账号都能看到(共用) |
| E3 | 只有 owner 能下架/发布/编辑动作 | 普通账号界面无入口;直接调 API 返回 403 |

## 6. 已知边界(出现时不算 bug)

- 离线"修改已发布计划"在另一台设备也改过同一计划时,同步后该操作标记"需人工处理"(`needs_attention`),数据不会静默覆盖——当前按设计如此。
- 离线完成训练后,重量建议不会弹出(建议接口需要联网);联网后完成才会弹。
- 免费 Apple ID 真机签名 7 天过期,需重连 Mac 重签(见 iOS 文档)。

## 完成标准

A1–A6、B1–B6、C1–C6、D1–D5、E1–E3 全部符合预期 → 进入 iOS 阶段。
